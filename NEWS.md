## Milestone 9, package P4: intermediate lessons robust, regression, glm (DE) (accepted, merged into main)

- Dataset check: `usability` already has `success` (0/1; the 4 timeouts at 180 s are all failures) and `errors` (Poisson counts, B halves the rate, dispersion ratio 1.55 in `errors ~ prototype`). Enough for logistic and Poisson regression, so no new column.
- Lessons (German, `langs: [de]`): `robust-intermediate` (rank tests with rstatix: Mann-Whitney, signed-rank, Kruskal-Wallis, Friedman, effect sizes r / rank-biserial / Kendall's W, Hodges-Lehmann shift; 20 % trimmed means with WRS2 `yuen()`; what rank tests compare), `regression-intermediate` (multiple regression on the `acceptance` scale scores, standardised coefficients, hierarchical comparison with `anova(m1, m2)`, interaction usefulness × experience with centred predictors and simple slopes, diagnostics with performance), `glm-intermediate` (logistic regression on `success` with odds ratios, `avg_predictions()`/`avg_comparisons()` from marginaleffects with cluster-robust SEs by participant, Poisson regression on `errors` with rate ratios, overdispersion and quasipoisson). 3 required + 1–2 optional exercises each, at least one `interpret` or `debug`, 5 knowledge-check questions.
- Migrated from legacy (triage 35): `rb-i-mann-whitney` (per-participant means, `female`/`male`, rstatix `wilcox_test()` + `wilcox_effsize()` instead of `wilcox.test()` and a hand-computed r). New: `rb-i-yuen`, `rb-i-friedman-read` (interpret), `rb-i-friedman-debug` (incomplete block p07), `rg-i-hierarchical`, `rg-i-interaction`, `rg-i-interaction-read` (interpret), `rg-i-standardized`, `gl-i-logistic`, `gl-i-comparisons`, `gl-i-poisson-debug` (missing `family`), `gl-i-odds-read` (interpret), `gl-i-overdispersion`.
- Decision: `regression-intermediate` uses `acceptance` (built-in usefulness × experience interaction); the moderation lesson (P5) goes deeper with Johnson-Neyman and the interactions package. Scale scores leave out the weak item `pu_5`, as concluded in the scales lesson.
- Decision: GLMs on the 284 task rows use cluster-robust SEs by participant (`vcov = ~participant`, needs sandwich) instead of ignoring the repeated measures; mixed GLMs follow in the mixed-models lesson. The overdispersion exercise uses `quasipoisson` rather than `MASS::glm.nb()`, because attaching MASS would mask `dplyr::select()`.
- Decision: no new check type. `lm`/`glm` results are compared as `model_parameters()` tables, `avg_comparisons()` and `anova()` as data frames; the browser compares user and solution with the same package versions (webR has marginaleffects 0.32, parameters 0.28, local 1.0/0.30).
- CI: `rstatix`, `WRS2`, `marginaleffects`, `sandwich` added to `.github/workflows/site.yaml`. Smoke test section 11: load times of the three lessons; Yuen solution, centred interaction and cluster-robust comparisons (hint for missing `vcov`, solution) graded in webR.

## Milestone 9, package P3: dataset acceptance; intermediate lessons scales, sem, group comparisons (DE) (accepted, merged into main)

- New dataset `acceptance` (`data-raw/acceptance.R`, `data/acceptance.csv`, entry in `data/datasets.yml`): TAM questionnaire after a test drive with a driver assistance system, n = 300; usefulness `pu_1`–`pu_5`, ease of use `peou_1`–`peou_4` (`peou_3` reverse-keyed), trust `trust_1`–`trust_5` (`trust_4` reverse-keyed), intention `bi_1`–`bi_4`, all 1–7; age, gender, `experience` (years with driver assistance). Built in: weak item `pu_5` (λ ≈ .37), four-factor CFA fits well (CFI .99, RMSEA .02), ease → usefulness → intention (for mediation), usefulness × experience (for moderation). Tests: structure, reverse-keyed items correlate negatively, one weak item, four-factor fit.
- Lessons (German, `langs: [de]`): `scales-intermediate` (α and ω for several scales with `psych::reliability()` and minus keys, item analysis with `r.drop`/"alpha if dropped", parallel analysis and EFA with oblimin), `sem-intermediate` (CFA with lavaan, fit indices and cut-offs, standardised loadings, nested comparison with `lavTestLRT()`, ω from the model with `semTools::compRelSEM()`, SEM outlook `bi ~ pu + peou + trust`), `group-comparisons-intermediate` (repeated-measures and mixed ANOVA with `afex::aov_ez()`, η²G, Greenhouse-Geisser, contrasts with emmeans and modelbased, Holm, excluded participants with missing cells). 3 required + 1–2 optional exercises each, 5 knowledge-check questions.
- Migrated from legacy (triage 30, 31, 36, 37, 38): `gc-i-rm-anova` (afex instead of `aov()` + hand-computed η²), `gc-i-contrasts` (emmeans + Holm instead of `TukeyHSD()`), `gc-i-paired-debug`, `gc-i-holm-predict`, `gc-i-assumptions` (performance on the model instead of Shapiro on raw data). New: `sc-i-reliability`, `sc-i-item-analysis` (interpret), `sc-i-efa`, `sc-i-reverse-debug` (`6 - x` on a 1–7 scale: α unchanged, mean off by 0.5), `sm-i-cfa`, `sm-i-loadings`, `sm-i-fit-read` (interpret), `sm-i-omega-debug` (ω from an unreversed model drops to .61), `sm-i-compare`.
- Value check for fitted models (`lavaan`, `afex_aov`, `merMod`): compared through `parameters::model_parameters()` — same parameters (name columns; `a ~~ b` equals `b ~~ a`) and the same `Coefficient`/`F`/`df`/`df_error`. Feedback names missing and extra parameters (max. 4, then "…") or the columns whose values differ. Tests with lavaan (other order, missing item, reversed item, wrong class) and afex (`aov_ez` vs. `aov_car`, other data).
- Decision: `sc-i-efa` returns item and highest loading without factor names, because `fa()` numbers the factors ML1–ML4 differently from run to run in webR (the first browser test failed on column order).
- Decision: `psych::reliability()` is called with its namespace; semTools exports a function of the same name, which masked it in the self-test.
- Smoke test section 10: load time scales-intermediate (psych, GPArotation) 12.7 s, sem-intermediate (lavaan, semTools) 12.2 s, group-comparisons-intermediate (afex, emmeans, modelbased) 23.8 s locally; EFA solution, lavaan model (hint for a missing factor, solution) and afex ANOVA (hint for missing `na.rm`, solution) graded in webR.
